01 / Perspective

Reliability as a first principle.

I approach backend engineering through the discipline of predictability and resilience. Distributed systems inherently fail in complex ways; writing idiomatic, concurrent Go with disciplined error propagation and transactional boundaries is how I build software that survives production.

My focus centers on designing backend platforms that handle real traffic: from multi-service monorepos with double-entry ledger engines to asynchronous job queues with exponential backoff and dead letter recovery.

I prioritize clean architectural boundaries (Hexagonal and Clean Architecture), strict schema modeling in PostgreSQL, and asynchronous coordination via Apache Kafka over brittle point-to-point integrations.

02 / Selected Work

Case studies in distributed engineering.

[ Case Study 01 ] Team Project · Microservices Monorepo
Repository ↗

MoneyMate

Distributed Personal Finance Platform — 7-Service Go Monorepo

A production-grade financial platform architected as a modular 7-service Go monorepo encompassing authentication, API gateway, payments, merchant workflows, rewards, notifications, and customer support. Engineered around strict double-entry ledger accounting to eliminate balance drift and race conditions during concurrent financial transactions.

Technical Decisions & Architecture
Double-Entry Ledger Engine

Implemented immutable credit/debit transaction pairing with PostgreSQL row-level locks, guaranteeing zero balance discrepancies during high-throughput concurrent transfers.

Transactional Outbox Pattern

Integrated Apache Kafka with outbox tables in PostgreSQL, preventing dual-write state corruption between local database commits and distributed event publication.

End-to-End Distributed Tracing

Instrumented services using OpenTelemetry and OTLP exporters, enabling trace propagation across HTTP gateway hops and internal gRPC/Kafka boundaries.

Type-Safe Persistence

Utilized SQLC and pgx for compile-time verified query generation, eliminating runtime ORM overhead while retaining clean relational schema migrations via Goose.

Stack: Go Fiber v3 PostgreSQL Redis Apache Kafka SQLC Docker OpenTelemetry Razorpay
[ Case Study 02 ] Solo Project · High-Throughput Engine
Live Platform ↗ Repository ↗

Sendr

Transactional Email Dispatch Platform & Developer CLI

A developer-centric transactional email platform constructed with Hexagonal Architecture. Features a custom asynchronous dispatch queue with resilient failure mitigation, token management with cryptographic rotation, and a cross-platform command-line tool designed for headless integration.

Technical Decisions & Architecture
Asynchronous Job Queue & DLQ

Constructed an in-house PostgreSQL-backed job queue processed by a concurrent goroutine worker pool with exponential backoff retries and Dead Letter Queue recovery.

Asymmetric JWT Auth & Rotation

Architected authentication using RS256 asymmetric keys, refresh token rotation, and Redis-backed blacklisting to invalidate revoked sessions in sub-millisecond lookups.

Hexagonal Domain Isolation

Decoupled core domain logic from external dispatch providers (SendGrid) and HTTP adapters, allowing provider interchangeability without touching business rules.

Native Developer CLI

Built and distributed a command-line utility in Go using Cobra, enabling engineers to trigger transactional templates and inspect queue telemetry directly from the terminal.
